The downloaded 128-episode dataset's `action` and `observation.state` arrays are six-dimensional, ordered shoulder pan, shoulder lift, elbow flex, wrist flex, wrist roll, gripper. The five arm values are calibrated joint positions in degrees; the gripper uses LeRobot's 0–100 range. They are **not raw servo ticks**, torque commands, PID logs, mechanical stop measurements, or a transferable calibration. Each arm's homing offsets, physical range, wiring and table clearance still have to be measured on that arm. The local exact-arm calibration remains `~/.cache/huggingface/lerobot/calibration/robots/so_follower/care_reach_follower.json`; do not replace it with someone else's JSON.

For motion-profile context, the 128-episode dataset's 99.5th-percentile absolute **action change per 30 Hz frame** is `[2.46, 3.43, 3.43, 1.93, 2.64, 6.37]` in its respective degrees/percent units. These are observed demonstration statistics, not safe limits for this arm.

## Control code already solved in part

The downloaded [`deployment/async_chunk_controller.py`](ddduk_act35_real_sim_v1/deployment/async_chunk_controller.py) is an isolated, model-independent controller. It discards stale policy actions, anchors new chunks to the current command, blends overlapping chunks, limits action displacement and acceleration per control tick, and stops on tracking error. Its example defaults include per-joint displacement and acceleration limits derived from demonstration data. This is useful source code for future policy deployment and motion smoothing after adapting its **degree/percent** units to this robot and enforcing this arm's saved tick bounds. No integration has been made.

Installed LeRobot **0.6.2** also has `interpolation_multiplier` for policy action interpolation and `max_relative_target` for clipping each goal near the measured position. The SO-101 follower driver already supports configurable P/I/D gains and `disable_torque_on_disconnect`. These features help with motion quality; they do not measure this arm's physical limits or define its coiled rest pose. See [LeRobot SOFollower source](https://github.com/huggingface/lerobot/blob/main/src/lerobot/robots/so_follower/so_follower.py) and [rollout configuration](https://github.com/huggingface/lerobot/blob/main/src/lerobot/rollout/configs.py).

## Do not run the downloaded rollout script as-is

- Its `SO101FollowerConfig` uses LeRobot's default **`disable_torque_on_disconnect=True`**. The script's shutdown calls `robot.bus.disconnect(robot.config.disable_torque_on_disconnect)`, which can drop a holding arm. Lance's requested rest procedure is to move to a verified coiled pose **before** torque release. That pose has not been recorded yet.
- LeRobot's normal connection/configuration path also temporarily disables torque to configure motor mode/gains. Do not start it while the arm is holding a pose until this interaction is handled deliberately.
- The model requires two correctly ordered cameras and a matching scene/task. Only the six-servo arm is confirmed here; the cameras and task setup are not yet verified. Its output normalization requires the exact arm calibration and limits.
- Its own [deployment readme](ddduk_act35_real_sim_v1/deployment/README.md) warns that the stock rollout path differs from the evaluated async controller. It also notes that the author tested LeRobot 0.6.1 with NVIDIA CUDA. A dry run on this Mac's LeRobot 0.6.2 and camera check must precede any robot execution.

The first reusable step is to adapt the downloaded motion planner's slew/acceleration limiting to the existing guarded joint controller. Policy inference can follow after cameras, normalization, coiled rest behavior and torque-preserving disconnect are verified.
